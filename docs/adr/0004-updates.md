# ADR 0004 — Updates: checksummed releases now, signed auto-update once public

**Status:** accepted · 2026-11-17

## Context

Cortex is a gatekeeper for what agents may run, so the update channel is the
most valuable thing an attacker could take over. ADR 0002 also promises that
the app makes no network traffic the user did not ask for. Today the repository
is private, so nothing the app could poll (release metadata, an update
manifest) is reachable without a credential — an updater cannot even be tested
end to end yet.

## Decision

1. **v1 ships with no in-app update check.** The app makes zero network calls
   of its own. Installers are built by CI from a tag, attached to a GitHub
   release with their SHA-256 checksums, and the release is published by a
   human. Settings shows the running version.
2. **When the repository is public, add signed auto-update** with the official
   `tauri-plugin-updater`: artifacts signed with a project-owned minisign key
   (private key and its password only in GitHub Actions secrets, public key
   compiled into the app), manifest served from the GitHub release. An update
   that fails signature verification is never installed.
3. **The check is opt-in and disclosed.** It is the first request Cortex makes
   on its own, so it is a visible setting ("Check for updates"), off until the
   user turns it on, and it sends nothing but the request for the manifest.

## Consequences

- Until step 2, users update by downloading a new installer. Acceptable while
  the audience is the author and early testers.
- Step 2 adds an HTTP/TLS stack to the dependency tree. It is accepted only
  through the official Tauri plugin and goes through `cargo deny` like the rest.
- The signing key becomes a critical secret: losing it means users must
  reinstall by hand; leaking it means rotating the key in a release signed by
  the old one. The key is generated by the maintainer, never by CI or an agent.
- OS-level code signing (Apple Developer ID, Windows certificate) is a separate,
  paid decision. Until then macOS builds are ad-hoc signed and need an explicit
  first-run approval, documented in the README.
